# Architecture and remaining engineering work

One worker serializes a bounded queue of 32 IPC requests, owns SQLite/arboard, and emits invalidation events. UI search is debounced; response sequence counters prevent stale search results replacing newer ones. Lists page 200 rows. A second WebView hosts keyboard-first Quick Popup. Single-instance handling reveals the main window, or the popup when invoked with --popup. Global shortcut registration is skipped on Wayland; bind the compositor instead.

The worker polls at 750 ms with error backoff. Native clipboard notifications and wl-paste --watch negotiation remain future work. This has explicit limitations: intermediate values may be missed; identical consecutive copies cannot be counted reliably; native API calls may block beyond the application's control. Quit sets the worker stop flag and joins it after in-flight work. Native calls still need platform-specific timeout validation. wl-clipboard subprocess I/O is bounded and has a two-second wait deadline.

Schema v1 creates text history and FTS5 triggers. Schema v3 adds optional Windows source metadata. Schema v2 adds favorites, image paths, settings, snippets, tags, collections and many-to-many relations with cascading deletes. Newer versions are rejected; v1 to latest upgrades are tested. Inserts and text retention run transactionally. Pins survive retention. Image files are written through temporary PNGs and renamed before metadata is stored. Referenced names are validated; startup and deletion reconcile orphans. Image metadata insertion and pruning can leave recoverable orphan files after interruption; startup reconciliation repairs them. Retention applies at startup, insertion and settings save.

The filesystem store holds PNG images, not SQLite blobs. Pixel content and dimensions are hashed. Native decoders are controlled by arboard; the application only enforces capture limits after arboard has decoded the image. Wayland PNG decoding applies allocation/dimension limits. Large native images can therefore temporarily consume more memory than the configured storage entry limit. Add native MIME/dimension preflight before production.

Incognito and pause stop capture while retaining the clipboard backend for selection ownership and manual restores. Pause is session-only; incognito persists. On resume the current value may be recorded. An optional small marker detector skips recognizable private keys and a few token prefixes. This is not password protection. No encryption is implemented. Windows uses best-effort clipboard-owner process attribution and executable-name exclusions; unknown owners cannot be excluded. Linux source attribution/exclusions are unavailable.

No shell is invoked with clipboard text. Commands are never executed. Core IPC accepts only typed action variants. Web content has a restrictive CSP and no remote resources. Autostart permissions are limited to enable/disable/status; recording never silently enables startup. No automatic paste or updater plugin is present.

Settings changes currently register the shortcut and update desktop behavior before database persistence; a database write failure could leave session-only desktop behavior different from persisted settings. Treat failed saves as failed and restart after fixing storage. Native tests are needed for focus restoration, shutdown, tray availability and shortcut conflicts. Partial localization and light-theme coverage require visual QA.
